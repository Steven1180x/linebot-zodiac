各位老師、同學好，我是報告人鍾名宣

我今天要報告的期中專案主題是：Line Bot 星座運勢指南：微服務架構與雲端部署實踐

本專案的核心，是利用 Python Flask 開發通訊邏輯，結合 LINE Messaging API 做為使用者互動介面，

並最終將整個服務部署至 Render 雲端平台，實現一個 24 小時不間斷運作的自動化聊天機器人服務。

接下來將為大家介紹本專案的開發背景與技術細節。1


首先介紹本專案的背景：『從本機腳本到 24 小時可用的服務』。

第一，我們的核心目標：是希望能提供使用者一個隨時隨地、24 小時不間斷的即時星座運勢查詢工具。

第二，在痛點分析部分：在開發初期，我們通常會在自己電腦上執行程式，並搭配 ngrok 這類工具穿透內網進行測試。但這種方式有很大局限

——只要電腦關機、網路斷線，或 ngrok 網址改變，服務就會立刻中斷，完全無法滿足實際發布給用戶使用的需求。

第三，因此我們的解決方案：是建立標準的 DevOps 部署流程。透過 Git 進行版本控制並託管至 GitHub，

再整合 Render 雲端平台自動進行 CICD 部署，順利將本機程式轉化為真正的雲端微服務。」2



「接者介紹系統的架構設計。我們透過 『四層架構串起 LINE 訊息與運勢回覆』：

第一層，使用者層：使用者在手機的 LINE App 輸入星座名稱發出訊息。

第二層，訊息傳輸層：LINE 官方伺服器接收到訊息後，透過 Webhook 機制（Messaging API），將資料即時打包推送到我們的伺服器網址。

第三層，雲端服務層：這部分是由 Render Web Service 託管我們的 Python Flask 後端程式，負責接收 Webhook 請求並確保服務穩定運行。

第四層，核心邏輯層：後端程式拿到請求後，會解析星座關鍵字，比對運勢資料，最後自動組裝成客製化的運勢卡片，再透過 LINE API 回傳給使用者。

透過這樣分層明確的架構，能讓訊息收發與資料處理保持極高的效率與穩定度。」3


「在技術選擇上，我們使用了四個關鍵組件，達到『技術棧各司其職，支撐完整部署流程』：

第一，後端開發：我們選用 Python 3 搭配 Flask 輕量化 Web 框架。Flask 語法簡潔且啟動快速，非常適合用來建構微服務架構的 Webhook API。

第二，API 整合：採用官方提供的 line-bot-sdk，讓我們能精準對接 LINE Messaging API，進行安全驗證與訊息事件處理。

第三，版本控制：使用 Git 進行程式碼版控，並將專案託管於 GitHub 儲存庫，作為自動化部署的核心樞紐。

第四，雲端託管：選擇部署在 Render 雲端平台，並搭配 Gunicorn WSGI HTTP 伺服器來處理併發請求，確保服務穩定運行。

這四個工具互相搭配，構建出完整且高效率的開發與部署生態。」4


「這頁展示的是我們後端程式的核心邏輯：從 Webhook 到個人化運勢卡片。   大家可以看一下右邊這段程式碼精華：

第一步，訊息監控：我們設定了 /callback 路由接收 LINE Webhook 請求。   

第二步，身份驗證：運用 Channel Secret 驗證數位簽章（如程式中的 handler.handle），確保訊息安全性。   

第三步，關鍵字匹配：接著系統會解析使用者傳來的文字，自動辨識十二星座關鍵字。   

第四步，動態生成：最後隨機抽樣幸運色與幸運數字，打包成結構化訊息回傳給使用者。」5


「接下來這頁是我們在實際開發與部署過程中，所進行的 『部署排除障礙，讓服務穩定上線』：

第一個挑戰：在初次提交 Git 時，因為將 Python 自動生成的巨型 .cache 暫存檔一併寫入，導致推送到 GitHub 時整個上傳過程卡住。

對應的解決方案：我們配置了 .gitignore 檔案來忽略這些非必要暫存檔，並執行 git rm -r --cached . 指令清理過往快取，成功讓專案瘦身

，大幅提升了推送速度。   第二個效能調整：在雲端測試時，我們深入研究了 Render 免費實例（Free Instance）的 Spin Down 自動休眠機制。

了解閒置一段時間後首次喚醒會導致請求逾時（Timeout）的原因，並掌握了優化首次喚醒回應時間的運作原理。   透過這些實戰除錯經驗，

我們不僅克服了部署關卡，也更深入理解了版本控制與雲端服務的運行細節。」6


「在排除所有部署障礙後，我們迎來了最終成果：『LINE Webhook 驗證成功，機器人正式上線』。

本專案呈現了四大核心優勢：

第一，成果表現：通過 LINE Webhook 官方驗證（Verify Success），確認雲端伺服器與 LINE 平台之間的雙向連線完全正常，機器人已穩定上線。

第二，跨平台使用：使用者無需下載額外的 App，只要打開平常習慣使用的 LINE，搜尋或加入機器人即可開始互動。

第三，免關機服務：因為程式已經託管至雲端平台，開發者個人電腦就算關機，服務依然保持 24 小時不間斷運作。

第四，秒級自動回覆：使用者只要輸入星座關鍵字，系統便會即時運算並秒級回覆當日運勢卡片。」7


「最後來到總結與未來展望：『完成從 API 開發到雲端部署的完整實踐』。

首先在專案總結：我們成功整合了 Python API 開發、Git 版本控制與 Render 雲端部署的完整流程，將一個單純的後端腳本落地為 24 小時穩定的線上微服務。

未來針對系統的升級，我們規劃了三個擴充方向：

以上是我的報告，謝謝聆聽！歡迎老師與同學提問。」8
